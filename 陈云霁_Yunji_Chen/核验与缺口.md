## 对奖励设计的直接线索

[QiMeng-PRepair README](https://github.com/kcxain/QiMeng-PRepair) 明确说明 EA-GRPO 采用两层评分：样本层执行测试并计算修复前后的行级编辑距离；组层根据正确率门槛决定是否对正确样本施加标准化编辑代价惩罚，低正确率时回退到正确性为主的奖励。路径为 `verl/verl/workers/reward_manager/alpha.py`（`AlphaRewardManager`）和 `reward/dynamic_sigmoid_verilog.py`；这次核验读到的是作者 README 的实现说明，未执行环境。其可迁移启发是“先满足功能正确，再约束修改代价”，不是已经验证的 EEG 或情感奖励。

CodeV-R1 的奖励实现入口在 `verl/verl/utils/reward_score/codev_eval_toolkit`（作者 README）；KernelZero 将正确性和性能评估用于 GPU 内核代码迭代。二者的奖励依赖代码执行/硬件性能，不能直接改名为“脑电奖励”。ESPL/CSRO 依赖环境交互或离线控制轨迹，其数据与 EEG 也不同。
